# dirtofile — спецификация поведения

Единый контракт для реализаций **Rust** и **Go**. При изменении CLI обновляйте этот файл и тесты в обеих версиях.

## CLI-флаги

| Флаг | По умолчанию | Описание |
|------|--------------|----------|
| `-d`, `--directory` | `.` | Исходный каталог (должен существовать и быть директорией) |
| `-o`, `--output` | — | Выходной файл (**обязателен**) |
| `-r`, `--recursive` | `false` | Рекурсивный обход подкаталогов |
| `-v`, `--verbose` | `false` | Подробный вывод |
| `-q`, `--quiet` | `false` | Тихий режим; отключает `-v` |
| `--force` | `false` | Перезаписать существующий выходной файл |
| `-i`, `--include` | — | Glob-шаблоны включения (повторяемый) |
| `-e`, `--exclude` | — | Glob-шаблоны исключения (повторяемый) |
| `--compression` | `6` | Уровень gzip 0–9 (только `tar.gz`) |
| `--format` | `tar.gz` | `tar.gz`, `tar`, `custom` |
| `--follow-links` | `false` | Следовать симлинкам |
| `--max-depth` | `-1` | Макс. глубина (`-1` = без лимита) |
| `--max-files` | `0` | Макс. число файлов (`0` = без лимита) |
| `--max-total-size` | `0` | Макс. суммарный размер в байтах |
| `--max-file-size` | `0` | Макс. размер одного файла |

## Обход каталога

### Без `-r`

Упаковываются **только файлы** непосредственно в корне `-d`. Подкаталоги не обходятся.

### С `-r`

Обход всех вложенных файлов с учётом `--max-depth`.

### Симлинки

| `--follow-links` | Поведение |
|------------------|-----------|
| `false` | Симлинки пропускаются |
| `true` | Цель резолвится; упаковывается только если канонический путь **внутри** канонического корня `-d` |

Симлинки на каталоги при `--follow-links` не упаковываются как файлы.

### Ошибки доступа

- **Go / Rust:** ошибка доступа при обходе → **прерывание** с ненулевым кодом.

## Фильтрация (glob)

- Поддерживаются `*`, `?`, `**`, классы `[...]`.
- Шаблон проверяется против **относительного пути** и **имени файла**.
- Если задан хотя бы один `--include`, файл должен совпасть с одним из них.
- `--exclude` имеет приоритет над `--include`.

## Выходной файл (`-o`)

1. Родительский каталог выходного файла должен существовать.
2. Если `-o` существует и это **каталог** → ошибка.
3. Если `-o` существует и это **файл** → ошибка без `--force`.
4. С `--force` существующий файл перезаписывается.

## Безопасность путей в архиве

- Запрещены абсолютные пути и сегменты `..` (tar slip).
- Внутри tar пути нормализуются с `/`.
- В custom-формате запрещены `\n` и `\r` в путях.

## Форматы

### `tar` / `tar.gz`

Потоковая упаковка: файлы записываются при обходе, полный список в RAM не хранится.

### `custom`

1. Проход подсчёта файлов (с учётом лимитов).
2. Заголовок `DIRTOFILE_ARCHIVE_v1` + число файлов.
3. Второй проход записи содержимого.

## Согласованность (TOCTOU)

Атомарный снимок файловой системы **не гарантируется**. Перед записью каждого файла повторно проверяется размер; при изменении — **ошибка**.

## Лимиты ресурсов

При превышении `--max-files`, `--max-total-size` или `--max-file-size` упаковка прерывается с ошибкой.

## Тестирование

| Набор | Расположение |
|-------|----------------|
| Unit / integration (Go) | `go/*_test.go` |
| Unit / integration (Rust) | `rust/src/main.rs` (`#[cfg(test)]`) |
| Golden fixtures | `testdata/fixtures/`, `testdata/golden/` |
| Cross-impl golden | `scripts/golden_compare.sh`, CI job `golden` |
| Symlinks (Unix) | `go/symlink_test.go`, Rust `#[cfg(unix)]` tests |
| Fuzz / property | `go/pathutil_fuzz_test.go`, Rust `proptest` в `main.rs` |
| Large files | `go/large_file_slow_test.go` (`-tags slow`) |
| Permissions (Unix) | `go/permissions_test.go`, Rust `unreadable_file_fails_walk` |

Ожидаемый listing для `testdata/fixtures/standard` с `-r`: см. `testdata/golden/standard-recursive.txt`.
