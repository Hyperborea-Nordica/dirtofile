# dirtofile

CLI утилита для упаковки содержимого директории в один файл. Поддерживает рекурсивный обход, фильтрацию файлов, сжатие и различные форматы вывода.

## Реализации

Проект содержит две реализации утилиты:
- **Go версия** (`go/`) - кроссплатформенная, с использованием стандартной библиотеки и cobra
- **Rust версия** (`rust/`) - высокопроизводительная, с использованием clap и современных библиотек

## Сборка

### Go версия

```bash
cd go
go mod tidy
go build -o dirtofile-go main.go
```

### Rust версия

```bash
cd rust
cargo build --release
# Бинарный файл будет в target/release/dirtofile
```

### Быстрая сборка (с использованием Makefile)

```bash
make all
make test-unit      # go test + cargo test
make test-golden    # сравнение Go/Rust с testdata/golden (Linux/macOS/Git Bash)
```

### Тесты

```bash
# Go
cd go && go test -v ./...

# Rust
cd rust && cargo test

# Golden (обе реализации + эталонный список имён в tar)
bash scripts/golden_compare.sh
# Windows PowerShell:
# powershell -File scripts/golden_compare.ps1

# Fuzz (Go, Linux/macOS)
cd go && go test -fuzz=FuzzSanitizeArchivePath -fuzztime=30s .

# Большие файлы (опционально)
make test-slow
```

## Использование

### Основной синтаксис

```bash
# Go версия
./go/dirtofile-go -d <directory> -o <output_file> [опции]

# Rust версия
./rust/target/release/dirtofile -d <directory> -o <output_file> [опции]
```

### Примеры

```bash
# Упаковать текущую директорию рекурсивно
dirtofile -d . -o archive.tar.gz -r

# Упаковать только .txt файлы
dirtofile -d docs -o texts.tar.gz -i "*.txt"

# Исключить .log файлы и node_modules
dirtofile -d project -o clean.tar.gz -r -e "*.log" -e "node_modules"

# Тихий режим с максимальной компрессией
dirtofile -d data -o compressed.tar.gz -q --compression 9
```

## Параметры

| Параметр | Короткий | Описание |
|----------|----------|----------|
| `--directory` | `-d` | Исходная директория (по умолчанию: `.`) |
| `--output` | `-o` | Выходной файл (обязательный) |
| `--recursive` | `-r` | Рекурсивный обход поддиректорий |
| `--verbose` | `-v` | Подробный вывод |
| `--quiet` | `-q` | Тихий режим (подавляет весь вывод кроме ошибок) |
| `--force` | | Перезаписать существующий выходной файл |
| `--include` | `-i` | Шаблоны включения файлов (glob, `**`) |
| `--exclude` | `-e` | Шаблоны исключения файлов (glob, `**`) |
| `--compression` | | Уровень сжатия (0-9, 0=без сжатия, по умолчанию: 6) |
| `--format` | | Формат вывода: `tar.gz` (по умолчанию), `tar`, `custom` |
| `--follow-links` | | Следовать символическим ссылкам |
| `--max-depth` | | Максимальная глубина рекурсии (-1 = без ограничений) |
| `--max-files` | | Максимальное число файлов (0 = без лимита) |
| `--max-total-size` | | Максимальный суммарный размер в байтах (0 = без лимита) |
| `--max-file-size` | | Максимальный размер одного файла (0 = без лимита) |

## Форматы вывода

### tar.gz (по умолчанию)
Стандартный tar архив со сжатием gzip. Совместим с утилитами `tar` и `gzip`.

### tar
Несжатый tar архив. Совместим с утилитами `tar`.

### custom
Пользовательский формат dirtofile:
- Заголовок с версией и количеством файлов
- Для каждого файла: метаданные (путь, размер, время модификации) + содержимое
- Разделители между файлами

## Шаблоны фильтрации

Поддерживаются glob-шаблоны:
- `*` - любое количество символов
- `?` - один символ
- `[abc]` - любой из перечисленных символов

Шаблоны применяются как к полному относительному пути, так и к имени файла.

Примеры:
- `*.txt` - все .txt файлы
- `src/**/*.rs` - все .rs файлы в директории src
- `test_*` - файлы, начинающиеся с test_

## Распаковка

### tar.gz и tar форматы
```bash
tar -xzf archive.tar.gz
tar -xf archive.tar
```

### custom формат
Для распаковки custom формата можно использовать простой скрипт или написать отдельную утилиту.

Пути в custom-формате не должны содержать символы `\n` и `\r`. Имена в tar нормализуются (разделитель `/`, без сегментов `..`).

## Безопасность

- **Tar slip:** относительные пути в архиве проверяются; сегменты `..` и абсолютные пути отклоняются.
- **Симлинки:** по умолчанию не следуют; с `--follow-links` в архив попадают только цели внутри канонического корня `-d`.
- **Ошибки обхода:** недоступные файлы/каталоги приводят к ошибке, а не к тихому пропуску.
- **Рекурсия:** без флага `-r` упаковываются только файлы в корне `-d` (без подкаталогов).
- **Лимиты:** `--max-files`, `--max-total-size`, `--max-file-size` защищают от чрезмерного потребления ресурсов.
- **TOCTOU:** при изменении размера файла во время упаковки операция завершается ошибкой.
